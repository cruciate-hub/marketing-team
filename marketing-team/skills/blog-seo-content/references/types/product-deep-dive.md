# Type: product-deep-dive

**For:** a shipped social.plus feature and when to use it; product announcements. Examples: a new moderation capability, a new SDK, a Console feature.

**Length:** 800-1,600 words. **Recommended:** a link to the feature's documentation (compliance WARNs without one).

## Structure

1. **Intro:** what shipped and the problem it solves, in one or two sentences.
2. **What it does** (H2): capabilities, stated precisely, from docs or release notes.
3. **When to use it** (H2): use cases, with a customer example only if approved.
4. **How it works** (H2): enough for a technical reader to judge fit; link to docs for setup.
5. **Getting started** (H2): the next step, availability, plan requirements.

## Rules

- Facts come from documentation and release notes checked on the day of writing. Add them to the evidence bank's Product facts if they will be reused.
- Coordinate with `product-update-vs-website`, `newsletters` and release notes so the same launch doesn't produce competing pages.
- No claims about impact without an approved figure.
