# Type: product-education

**For:** how to use a social.plus feature well: "How to prompt the MCP server for your industry use case", "How to use user tag filtering for segment-level sentiment". The one kind of how-to that stays on the blog, because it's about using our product rather than a general buyer or developer question.

**Length:** 600-1,600 words. **Required:** numbered steps (compliance FAILs without them). **Recommended:** a link to the relevant documentation page.

## Structure

1. **Intro:** what the reader will be able to do, and who it's for.
2. **Before you start** (H2): plan, permissions, setup assumed.
3. **Steps** (H2, or one H2 per phase): numbered, each opening with a verb, with the exact UI labels or API names from the docs.
4. **Examples** (H2): one or two worked examples for real use cases.
5. **Troubleshooting or tips** (H2).

## Rules

- The documentation is the source of truth. Check every step against it on the day of writing; link to it for anything that changes often.
- If the post is really "How do you [add X to an app]?" in general, it belongs to aeo-content, not here.
- Screenshots use `[IMAGE_URL]` placeholders with descriptive alt text.
