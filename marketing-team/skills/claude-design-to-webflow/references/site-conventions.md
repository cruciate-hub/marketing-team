# Site conventions (social.plus Webflow)

How social.plus pages are built in Webflow. Moved here unchanged from SKILL.md on 19 Nov 2026 (move table in the PR), except where marked **(updated 19 Nov 2026)**. Webflow is king: these conventions win over a board.

## Site conventions first — non-negotiable, before writing a single element
A design board shows how a page LOOKS; the site's components and conventions decide how it is BUILT. Rebuilding a button, link or icon by hand from the board's markup is the #1 failure of this skill (Developer Portal, 30 Oct 2026: hand-made buttons, missing link/SVG attributes, an open-bottomed frame grid — rejected outright). Before any `data_whtml_builder` call:
1. **Inventory the components** (`data_component_tool query_components` with keywords `button`, `link`, `icon`, `card`, `section`, `includeProps` + `includeInstanceCount`) and map every button, link, icon and recurring section on the board to one. Use an **instance** wherever a component exists (`insert_component_instance` + `set_component_instance_prop_values`); whtml builds layout and text only. social.plus mapping: primary blue → `Button / Primary` (any non-sales link) or `Button / Talk to Sales` (sales CTAs only: it carries the `talk_to_sales_button_click` tracking id); grey secondary → `Button / Tertiary`; inline text link → `Buttons / Text Link` (White / Blue variants); arrow → `Icon / Arrow`; external-link glyph → `Icon / External link`; nav, footer CTA and footer → the existing `Nav / Main`, `Section / Footer CTA`, `Section / Footer Main`. If no component fits, build bespoke and say why in the report.
2. **Links:** a clickable card is ONE Link Block (no nested links, the CTA inside is a div/span, see rule 6 for the classes). Card titles in a section with no visible h2 are h2, styled with a heading-size class (`h5-font-size`), whatever level the design used. External links: `static_link` with `open_in_new_tab: true` and NO `rel` (Webflow turns a `rel` value into a stray `<link rel="noopener">` element after the anchor — invalid HTML; browsers already apply noopener to `target="_blank"`), plus an `aria-label` that names the destination and says "(opens in a new tab)" when the visible text isn't self-describing ("Docs", "API"). Strip the raw `href`/`rel` attributes whtml leaves behind (Pitfall 23).
3. **SVGs:** decorative inline SVG gets `aria-hidden="true"` and `focusable="false"`, colour via `currentColor` (no inline `style`); where an Icon component exists, use the instance instead.
4. **Framed grids use the approved frame modifiers (31 Oct 2026, Developer Portal):** section `section padding_Y background-color_dark border-top` + combo `c-framed` (no top padding; the existing `border-top` is the full-width rule) > `page-padding` > `container-large` + `c-framed` (side lines) holding two `frame-marker` divs (`aria-hidden`, the right one + `is-right`) > `grid-4` + `c-framed` (1px gaps over the line colour, its own top line overlapping a section rule by 1px, bottom line) > Link Block `card-v1` + `c-cell` > `card-icon-v2` + `c-tile` (icon tile). The framed section closes with its own full-width bottom rule (the `c-framed` section combo: no top/bottom padding, `border-bottom`) and two more markers (`frame-marker is-bottom`, `frame-marker is-right is-bottom`), so the + sits on every line crossing, top and bottom. The container carries `display: flow-root` (no margin collapses through it), both marker rows use ±0.28rem, and two framed sections stacked directly share one line (`margin-bottom: -1px` on the section combo); never re-tune these offsets per page (Pitfall 94). Clickable cells get the design system's hover (background one step lighter: Social/Dark → Dark Gray Background, 200ms) and a `:focus-visible` ring in link blue, on the `c-clickable` combo (`card-v1 c-cell c-clickable`); `c-cell` alone is the static cell with no hover, for cells that are not links (Pitfall 80). Long-form pages with a table of contents (Trust, 31 Oct 2026): the framed section holds the blog layout, `blog-wrapper` > `blog-aside c-framed` (`toc-sticky` > the blog's `toc-embed`, Pitfall 79) + `blog-main c-framed` > a native Rich Text `rich-text c-blog` (Pitfall 78); the aside's right border is the frame line between TOC and text. Never on the hero: on a framed page the hero stays outside the frame (updated 19 Nov 2026). A framed component instance (`Section / Logo Wall`) is a whole framed section with its own markers: insert it as is, never wrap it in another framed section. Anything beyond these: ask Stefan first. A framed section never touches the nav or a sub-nav: when it is the first section on the page (no hero above it), put an empty `margin-top_L` div (50px, `aria-hidden="true"`) directly before it, as Talk to Sales does (Pitfall 95).
5. **Variables, never hex.** Every colour and font in a class binds to a Webflow variable (`variable_as_value`). Missing token → ask Stefan first, then create it in the `General` collection (`data_variable_tool create_color_variable` / `create_font_family_variable`) and bind. Variables added 30 Oct 2026 and not yet approved for general use: `Frame/Frame - Line` #202022, `Frame/Frame - Marker` #939497, `Text/Text Color - Link Blue` #6f89fc, `Border/Border - Tile` #29292b; `Font/Geist Mono` (eyebrow labels). Properties that can't take a variable (e.g. `-webkit-text-fill-color`) get `currentColor` and follow the bound `color`.
6. **Reuse the site's class system — never invent a parallel one.** Build every section the way the existing pages are built; read a section Stefan built (or the nearest existing page) with `query_elements children_depth:-1` and copy its skeleton. social.plus skeleton (Developer Portal header, built by Stefan 30 Oct 2026): `section` + `padding_Y` (tag `header`/`section`) > `page-padding` > `container-large` > `container-heading` (centred heading block) > `superscript` eyebrow + plain `h1`/`p` (global tag styles, no class: never a page-specific text class that re-declares size, weight or colour, Pitfall 136) + `button-group` with `Button / Primary` / `Button / Tertiary` instances. Grids (columns at main/medium/small/tiny, verified 30 Oct 2026): `grid-4` 4/4/2/1 (gap 2rem, row gap 4rem), `industry-grid-4` 4/3/2/2 (gap 1rem), `grid-3`, `grid-2`; `c-card_grid-4` is 2 columns despite its name. No existing grid gives 4→2 on tablet; Stefan decides the tablet column count per page, by content (sometimes 2 reads better, sometimes 4): ask him, and never override a shared grid without his OK. Whole-card link: Link Block with `card-v1` + `c-outline` > `card-content` (> `icon_wrapper` > Image `icon-medium`, heading `h5-font-size`, p `text-size-small`) + `card-footer` > `text-link` > `button-text` + an `Icon / External link` instance. Do NOT use the `Card / Button` component for a clickable card: its root is a div, only its nested `Button / Tertiary` links (repeating the title) and its Aria-label prop is unbound. Utilities: `heading-small`, `text-size-small`, `text-color-*`, `margin-*_S/M/L`, `icon_wrapper`, `icon-small/medium`, `border-top` combo. Class lists go stale (a class named here can be deleted): always confirm by exact-name query before use. Inventory first: `get_styles` (save to file, list names; `query_styles` `name_path` is a substring match, so `["grid"]` or `["card"]` with breakpoints overflows and hits the limit: query exact names) and `query_components`. A new class is allowed only when nothing existing can express the design, must use the site naming (`block_element`, `c-` combos), and is named in the report with the reason — ask Stefan before adding one. The Developer Portal rebuild that invented 20 `fr-` classes, a new card component and a hero next to the site's own was rejected (30 Oct 2026).
7. **Embeds only for what native styles can't do (updated 19 Nov 2026).** Fonts go in via `data_fonts_tool`, styles are native classes. A `<style>` HtmlEmbed is allowed only for states Webflow can't express natively (`:has()`, checked/`:checked`, keyframes, attribute selectors), placed **inside or right beside the section or element it styles** and scoped to that section's classes: several small embeds next to their elements, never one general embed for the whole page, never page head code, never layout a native class can do (Stefan, 19 Nov 2026). Behaviour JS with no native equivalent goes in an embed in the component or section that owns it. Every embed is listed in the build report with what it styles. Never copy an embed from another page; an embed found on the page you touch that nothing on that page uses gets removed (check its selectors first) and reported.
8. **Gate before staging** — verify by query, not by eye: every `<a>` is a component instance or a Link Block with a `link` setting; no element carries a raw `href` attribute; every inline `svg` has `aria-hidden` + `focusable`; every new `HtmlEmbed` follows rule 7 (state CSS or behaviour only, next to what it styles, listed in the report); every framed grid has its bottom line; every `frame-marker` centre is within 0.6px of its line crossing at 1440 and 390, and no two adjacent sections draw a double rule (Pitfall 94); no hex colour left in a new class (`query_styles` with `include_properties`). Fail any check → fix first, then publish.

## Core principle
**Existing first, native second, code last.** Reuse the site's classes, components and variables; where something genuinely new is needed, make it a native Style record; code only for what Webflow can't express. `data_whtml_builder` builds **structure only** (DOM, tags, text, existing class names) — styling happens with `data_style_tool`.

## Build gates (adopted from Webflow's official build skill, 30 Oct 2026 — fail one → stop and fix or ask)
Decisions with their social.plus defaults (state them in one line at the start; ask Stefan only to deviate): **naming** = the site's existing classes (never FlowKit, never a new prefix); **variables** = existing variables, add a missing token only per rule 5; **units** = rem, always (Stefan: "we work in REM in Webflow"; convert design px at 16px = 1rem; px only for 1px hairlines and borders); **build mode** = headless Data API, Designer snapshots only if the tab is open.
- **Native style gate:** no `css` param in `data_whtml_builder` for normal styling — it lands in Custom properties instead of Style-panel controls. Styles go through `data_style_tool` (`create_style`/`update_style`, longhand properties, `variable_as_value` for tokens).
- **Class existence gate:** every class in whtml/`set_style` must already exist as a Style record (query it first); whtml can silently drop unknown class names. A new class is created with `create_style` before the whtml call — and only after Stefan approved it (rule 6).
- **Visible element gate:** no `::before`/`::after` or embed `<style>` for layout or decoration — invisible in the Navigator and unselectable. Decorative lines/markers are real elements with native classes, or left out. State-only CSS in an embed per rule 7 is the one exception.
- **Vector gate:** icons = the site's `Icon /` components first; otherwise clean inline SVG (`svg-icon-transformer` skill) with `aria-hidden` + `focusable="false"`. No PNG icons.
- **CSS gate:** longhand only; avoid `calc()`/`clamp()`/`min()`/`max()`, `@keyframes`, multi-layer shadows, logical props in native styles (they may be dropped); desktop-first breakpoints `main`→`medium`→`small`→`tiny`.
- **Capability gate:** never claim "Webflow/MCP can't do X" until you've tried the tool path; otherwise say "untested".
- **Verification gate:** done = rendered output checked (published staging HTML/CSS + a screenshot); say plainly what you couldn't verify.
- **Board parity gate (updated 19 Nov 2026):** before reporting a Claude Design build as done, re-read the board (`Artifact read`) and run `scripts/check-board.mjs` (board vs staging at 1440/800/390: roles, frame lines per section, horizontal scroll, axe accessibility, internal links, live CSS; `references/check-board.md`). Every FAIL is fixed or named; every Webflow-owned difference is a NOTE and goes on the "Webflow won" list for the board (Pitfalls 124-134). Webflow is king: site tokens, gutters and components win over the board (Pitfall 134).
- **Publish gate (updated 19 Nov 2026):** "publish" means staging (`.webflow.io`), after the gates pass. Production only when Stefan says "publish to the real website", after warning that a production publish pushes every other unpublished change on the site.

## Native vs code decision
**Native** (`data_style_tool` Style record): single-class rules; combo classes (`parent_style_names`); supported pseudos (`:hover :focus :focus-visible :active ::before ::after :nth-child(odd/even) :first/last-child :focus-within …`); responsive breakpoint values; variable bindings (`variable_as_value`).
**Code** (freeform head/footer, or an HTML embed): `@keyframes`, `@property`; descendant (`.a .b`) + attribute (`[data-x]`) selectors; `:nth-child(N)`; custom / feature queries (`prefers-reduced-motion`); `color-mix()` (Designer corrupts it on save — keep in code, OR store it as a variable `custom_value` and bind the property to that variable); section-root `--var:` definitions descendants inherit; all JS behavior.

## Breakpoints (authoritative)
`main` = base/desktop (≥992) · `medium` ≤991 (`max-width:991px`) · `small` ≤767 (`max-width:767px`) · `tiny` ≤479 (`max-width:479px`) · up-scaling `large`≥1280 / `xl`≥1440 / `xxl`≥1920. **Styles cascade DOWN** (main→medium→small→tiny): set at `small` and it also applies at `tiny` unless overridden. In em: 48em=768, 47.9375em=767, 61.9375em=991, 29.9375em=479. Round Claude's odd breakpoints (1200/720/520) to these, or keep that `@media` block in code.

## Responsive & components
- **Make ONE component responsive** instead of shipping a mobile-duplicate: native breakpoint styles + (when a shared embed needs a mobile-only tweak) edit the shared CSS/JS embed once, scoping any JS with `matchMedia` so other breakpoints stay byte-for-byte identical. → worked-examples E/F. Component **variants** (`data_component_variants_tool`) give per-component style overrides for non-breakpoint variations.
- **Author a reusable component headlessly:** build one instance (`data_whtml_builder`) → `data_component_tool transform_element_to_component` → define props (`data_component_props_tool create_prop`) → **bind each prop to its element** (`data_element_settings_tool set_settings` with `binding {source_type:'prop'}`) → reuse via `insert_component_instance` + `set_component_instance_prop_values` (a `variant` value selects a variant per instance). Reuse a component only where the pattern **visually matches its default**; where the design diverges, build bespoke elements and say why — don't force the component.
- **Shared-class / shared-embed blast radius:** class names are global site-wide and embeds are frequently shared components — one `update_style` or embed edit hits every instance. Check reach with `data_component_tool` `includeInstanceCount`; usually a feature (consistent everywhere), but say so to the user. → Pitfall 18.
- **Removing a redundant component:** no bulk instance-delete exists and `unregister_component` errors while the component is in use → hand the user the Designer **right-click → Delete Component** (removes definition + every instance atomically, undoable). → Pitfall 20.

## Detailed checklist (the gates in SKILL.md summarise it)
- [ ] Skeleton copied from an existing section; every class used already existed (or Stefan approved the new one by name).
- [ ] No `css` param in any whtml call; styles via `data_style_tool`; every colour/font bound to a variable (no hex in a class).
- [ ] Buttons, icons, nav/footer = component instances; cards/links per rule 2 (one Link Block, new tab + aria-label for external).
- [ ] No raw `href` attribute; every inline SVG has `aria-hidden` + `focusable`; no `::before`/`::after` for layout or decoration; every new HtmlEmbed follows rule 7 and is listed in the report.
- [ ] Every size you wrote is in rem (px only for 1px borders).
- [ ] Responsive checked at medium/small/tiny; framed grids close at the bottom; every framed section's `borderBottom` measured on staging (the last section before the footer has no neighbour to hide a missing rule), and the framed container's top and bottom edges sit on the section's rules (no margin collapsing through).
- [ ] Every existing class you restyled was queried at medium/small/tiny and its old breakpoint values cleared; at 390px each framed section's top rule meets its "+" markers (Pitfall 82). Every "+" measured against its line crossing (under 0.6px) and no double rule between stacked framed sections, on every page that has `.frame-marker` (Pitfall 94).
- [ ] `scripts/check-board.mjs` run, its report attached (no FAIL left unexplained); staging published, screenshot taken; or, when the task says no publish, every unverified visual listed (columns per breakpoint, card padding, hover, contrast). Production untouched unless Stefan said "publish to the real website".
- [ ] Heading levels follow the page outline (one h1; section titles h2), not the design board's tags.
- [ ] **Semantic HTML check on the published staging HTML** (curl it, don't eyeball): exactly one `<main>` holding the page content between nav and footer (add one with `data_element_builder` `BY_CUSTOM_TAG` `main` and `move_element` the sections in); one `h1`, no skipped levels; a section without a visible heading has an `aria-label`; a grid of cards is a list (`role="list"` on the grid, each card wrapped in a plain div with `role="listitem"`); no `<link>` elements in the body; no invalid attribute values (e.g. `width="currentWidth"`); decorative images `alt=""`, decorative SVG/markers `aria-hidden`; every link has a name.
- [ ] Every clickable block has a visible hover and a `:focus-visible` state, and nothing that is not clickable has one.
- [ ] Lessons from this build added to `references/pitfalls.md` (new number, plus its one-liner in the index at the top of that file) before you finish; every "Webflow won" drift raised with Stefan for the board and the design system.
